How it works

The TikTok Shop integration, plainly

Affiliate Dashboard reads a creator's own affiliate data through the official TikTok Shop API and stores it on that creator's own machine. Here is every step, in order.

From authorization to dashboard

Four steps, all of them read-only.

1

The creator authorizes their own account

The creator connects their own TikTok Shop affiliate account using creator-type OAuth authorization. They sign in on TikTok's own page and approve the requested permissions there — the app never sees or handles their TikTok password.

Authorization can be revoked by the creator at any time from their TikTok account settings.

2

Three read scopes are requested

Each scope maps directly to one part of the dashboard. Nothing is requested “just in case”.

3

Data is read and stored locally

Using the granted access token, the app calls the TikTok Shop API for the creator's sample applications, fulfillment status, target collaborations, attributed orders, creator profile and showcase products. The responses are written to a SQLite database file on the creator's own machine.

There is no server, no hosted account, and no upload step. The dashboard reads from that local database.

4

The four views are assembled

Samples, collab invites, showcase and earnings are each rendered from the locally stored data — a single place to see what shipped, what arrived, what needs a reply, and what earned commission.

Permissions

Scopes requested, and why

All three are read scopes.

Every scope the app requests, and the part of the dashboard it powers.
Scope Access Why it is needed
creator.affiliate_collaboration.read Read Sample applications and their fulfillment status, target collaborations, and orders attributed to the creator's content. This scope powers the Samples, Collab invites and Earnings views.
creator.affiliate.info Read The creator's own profile, used to confirm which account the stored data belongs to and to label the dashboard.
creator.showcase.read Read The products currently on the creator's showcase, shown in the Showcase view alongside the samples and collaborations they came from.

No write scopes are requested

The app requests no scope that would let it create, update, delete, publish or send anything. It cannot accept a collaboration, reply to a message, apply for a sample, or change a showcase — those remain the creator's actions, taken in the TikTok Shop app.

This is enforced in the code as well as in the scope request: every outbound call is checked against an explicit allowlist of read endpoints, and any request that is not on that list is refused before it is sent.

Data flow

Nothing leaves the device

The path the data takes is short and has no third party in it:

TikTok Shop API → local machine → local SQLite

The app talks to TikTok's API to fetch the creator's own data and writes it to a database file on that same machine. It sends that data nowhere else. There is no analytics service, no hosted backend, no telemetry, and no third party with a copy.

Access tokens are stored in the same local database and are transmitted only back to TikTok's API, to authenticate the creator's own requests.

Deleting the local database file removes the stored data, because no other copy exists. See the Privacy Policy for the full detail.

An independent project
